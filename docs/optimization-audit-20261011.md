# 模型适配与写入链路优化审查

日期：2026-10-11。本轮为代码审查，未实施以下候选，也未调用外部模型。范围为上下文编译、写手消息、逻辑编辑、续写持久化、分支应用及对应 UI。保留独立 Provider、共享训练协议、项目资料、YOLO、备份和版本冲突检查。

后续实施：用户确认后，以下五项已完成。下文保留审查时的发现；实际行为见本节与用户指南。

- 生成、重试、接受正文和 Agent 共用保存检查；保存失败、目标变化或正文变化时停止。
- 默认编辑稿至少保留原稿一半字符；严重删减标记 blocked，YOLO 不能自动应用。续写界面提供“允许编辑压缩正文”，该选项保存在运行记录中；这只是完整性门禁，质量仍依赖独立复核与作者判断。
- 写手请求准备按完整 messages 序列化结果估算，去除重复前文，逐条移除可选文风、检索证据、项目资料，必要时缩短最近正文；保留锁定事实、人物状态和必要剧情线。续写同时参考 writer/reviewer 的独立窗口和输出预留。预算无法满足时明确报错。群组写手同样使用准备器，后续群组编辑仍由 Provider 校验完整消息。训练使用的 writer.v1 渲染器未改动，运行记录保存实际请求和消息。
- 来源校验按章节缓存原文；改写或删除的引用不进入有效上下文，锁定事实引用失效会停止编译。全文哈希变化但引用原句仍匹配时保留资料并提醒核对语义。原始项目资料与历史不被删除。
- 新布局为 `.inkforge/continuation/index.json` 和 `records/<运行 ID 的 SHA256>.json`。旧 runs.json 保留；迁移完成后只更新当前运行和小索引。列表读取最近 100 轮，较旧的记录和状态索引继续保留，以支持按 ID 读取和分支检查。迁移中断可以重试，备份包含新目录。
- 删除只被旧测试引用的 chooseUsableEditedDraft 回退函数。

已增加保存异常、长稿删减、窗口预算、失效引用、单章读取缓存、迁移中断、并发保存和备份恢复测试。Token 预算仍是估算，并非服务端 tokenizer 的精确计数；未调用在线模型，因此不宣称正文质量提升或实际推理性能倍数。

完成验证：404 个测试通过；类型检查、lint、桌面生产构建及桌面 IPC 冒烟通过；写手比较 CLI 离线冒烟通过（7 次模拟调用）。

## 优先修正

### 1. 合并保存检查，阻止保存失败后继续生成或应用

`useProjectStore.saveCurrentChapter` 捕获异常并设置 `saveState=error`，不会向调用方抛出。`ContinuationWorkbench` 的生成和接受按钮只 await 保存，随后调用生成/应用；`AgentChatPanel` 已有自己的保存检查。这会使续写基于磁盘旧版本生成，或者在磁盘仍匹配分支基线时应用分支，而编辑器还有未保存内容。

建议提供一个共用的保存并验证入口，检查保存状态及目标项目/章节；两处续写入口和 Agent 复用。属于合并重复行为，净删除量需实施后统计。风险是保存失败时 UI 行为变化，应该明确显示错误并停止后续动作。验证：模拟保存失败、保存中切章、保存期间再次编辑；确认未请求模型或应用分支。

### 2. 编辑完整性检查的阈值不适合长稿

`LogicReviewService` 使用 `revisedText.length < Math.min(200, draft.length * 0.5)`。4000 字草稿变成恰好 200 字不会触发拒绝；`ContinuationValidator` 的篇幅不足是软警告。若复核模型返回通过，严重删减可能进入可应用分支。

建议将最低绝对长度和相对保留比例分别表达，避免在一个 min 表达式中混合两种含义。过度缩短进入 blocked，作者明确要求压缩时采用单独规则。比例应经场景评测确定，不能宣称某个比例保证质量。验证：长稿缩至 200 字、正常局部纠错、作者指定压缩、短场景。

### 3. 统一按最终消息计算输入预算，减少重复前文

`ContextCompiler` 使用简略事实渲染文本和证据 excerpt 计预算，`buildWriterMessages` 实际发送完整对象 JSON，包括证据、哈希、偏移等额外内容。`ContinuationOrchestrator` 又加入最近 3600 字；当前章即时证据包含其中最多 1800 字，两处重叠。`assertCompletionFits` 能拒绝超限请求，但没有自动优化这份输入。

建议运行时读取所选模型窗口及实际输出预留，用共享构建器对最终 messages 估算预算；先去除完全重复前文，再按优先级移除可选完整条目，保留硬事实，装不下时明确停止或拆场景。不得截断 JSON 或静默删硬约束。减少编译器与发送器的两套预算逻辑；收益必须用固定样例测量。训练共用协议发生渲染变化时需记录版本，避免影响正在进行的数据准备。

验证：4K/8K 窗口、长中文与混合文本、事实超限、证据 JSON 开销、writer 和 reviewer 各自不同窗口。

### 4. 检索证据与正文资料在读取时缺少有效性核对

`ContextCompiler.allowedEvidence` 只检查章节位置和结束偏移；检索与文风范例的哈希、原句未与现存正文比对。`ProjectDataService.preview` 会校验新提案引用，但 `context` 读取已接受资料时只按故事位置筛选。正文后续被人工重写或回滚后，旧证据和旧状态可能继续传给模型。

建议合并为本次编译共享的来源校验缓存，一章只读/计算一次，失效证据从有效上下文剔除并单独报告。资料语义失效不能只靠全文哈希判断：正文追加会改变哈希，但可能保留旧原句；应区分“原句仍匹配”和“原句被替换”，保留作者处理入口。需要增加有限校验成本，正确性优先，不能直接删除全部旧资料。

验证：正文追加、原句替换、章节删除、正文回滚；统计同一章被多条证据引用时的文件读取次数。

### 5. 续写检查点整库重写，长篇生产成本会增长

`ContinuationOrchestrator.upsert` 在每阶段读取并重写最多 100 个完整 run。每个 run 保存 evidencePack、writerRequest、writerMessages、原稿、最终稿；logicReview 再保存部分相同正文。重复内容使每个阶段都重写历史大对象。

建议保留小型运行目录，每轮一个完整记录文件；每个阶段仅更新当前轮，兼容迁移现有 runs.json。精确 writerMessages 是协议审计工件，不建议直接删除。可减少全库读写和不必要解析，但新增文件布局需要迁移及备份验证，不能承诺尚未测量的性能倍数。

验证：100 轮长稿文件读写字节量、断点记录、历史迁移、备份恢复、多轮并发；检查点之间仍应有持久化边界。

## 可顺手移除的小项

`chooseUsableEditedDraft` 全仓库检索仅发现函数定义及测试调用；当前生产编辑流程没有调用，桌面服务也不是公共发布包 API。它保留了“编辑失败回退原稿”的旧行为，与现在的阻断规则相反。可删除约 7 行函数、导入和专用旧测试，改用实际编辑失败流程回归测试。删除前再次检查动态消费者与构建产物；不影响正常编辑行为。

## 暂不建议改动

- 不删独立复核：它是用户已接受的质量流程，不能为省一次调用取消。
- 不取消正文与资料版本检查、章节历史及 YOLO 备份。
- 不将各书的专属资料收敛为通用货币/装备/技能结构。
- 不将模型评估、段落保留率或原句哈希匹配宣称为语义正确证明。

建议顺序：保存检查和编辑完整性 → 最终消息预算 → 来源有效性 → 持久化拆分。小型旧 helper 清理随对应编辑修正一起进行。
