# 正文选区引用加入 Agent 对话

已实现用户指定的 Codex 注释式交互：正文选区通过“加入对话”成为待发送引用，消息输入区用计数按钮展开卡片；卡片展示原文与章节来源，支持添加批注和删除。允许多段引用，限制每章 8 条，并去重相同位置的同一文本。

实现复用现有 Agent 消息与提案流程，无需新增 IPC 或主进程写入通道。引用作为文本资料发送，原文保持不变；只有作者的消息和批注表达修改要求。引用内的 `@成员` 不会被当成作者指定 Agent 的操作。发送前预算、字符限制包含引用和导入文档。

引用暂存在按项目/章节隔离的前端 store 中，Agent 折叠或延迟挂载不会丢失引用。普通面板与窄窗口抽屉均能自动打开；无选区时入口禁用。成功发送移除本轮引用，失败或取消恢复；测试发现停止按钮在恢复表单内容后可能触发默认提交，已阻止默认行为并验证取消不会自动重发。

验证：

- 新增 5 项测试覆盖原文与来源序列化、同位置去重、每章数量限制、失败恢复时保留新引用、批注与原文分离。
- 浏览器流程验证无选区、精确选取、多段、批注、逐条移除、折叠后展开、切章隔离、失败与取消恢复、取消不重发、发送内容和清空、窄窗口抽屉及清空全部引用。
- 浅色、深色和 390px 窄窗口截图已检查，产物位于 `output/playwright/selection-chat-{light,dark,narrow}.png`。
- 全量测试、类型检查、lint 与生产构建的结果以本轮最后命令输出为准。

浏览器发送验证使用项目现有模拟 Agent，并注入失败/取消响应；本轮未调用付费模型，未据此宣称真实模型能精确理解或修改任意选区。待发送引用不持久化到项目，重启会清空。已有 YOLO 行为保持不变。
