# InkForge 下一阶段开发路线

## 产品核心：人工写作优先

InkForge 的核心仍然是作者亲自写作，AI 只是可选辅助，不会取代正文编辑器。

当前左侧“章节”页面就是人工写作工作台，已经支持：

- 直接输入和编辑 Markdown 正文。
- 编辑与预览视图切换。
- 自动保存、手动保存和保存状态提示。
- 字数、目标字数和章节完成度。
- 章节目标、备注、冲突点和状态维护。
- 专注写作模式。
- 历史版本预览与恢复。

后续应将导航名称和页面说明进一步明确为“章节写作台”，并继续补充纯手写能力：

- 在不进入全屏专注模式时单独收起 Agent 面板。
- 章节内查找替换、跳转标题和 Markdown 快捷格式。
- 打字机滚动、段落聚焦和更完整的键盘操作。
- 每日字数、写作时长和人工写作进度记录。
- 选中文本后的批注、书签和待修改标记。

这些能力不依赖模型配置，没有 API Key 也能完整使用。

## 已确定的开发范围

### 1. 自动备份与恢复中心

- 按时间或保存次数创建增量快照。
- 设置保留数量、备份目录和磁盘上限。
- 展示快照时间、变更章节和占用空间。
- 恢复前显示差异，恢复后保留回滚点。
- 项目损坏时提供完整性检查与安全恢复。

完成标准：任何章节、资料或大纲误操作都能在应用内找到并恢复。

### 2. 草稿箱与版本管理

- 按草稿、修订中、已完成、已归档筛选章节。
- 支持批量归档、恢复、移动分卷和修改状态。
- 聚合章节历史版本，提供差异预览。
- 支持未纳入章节树的片段和灵感草稿。
- Agent 可读取指定草稿，但写入仍需作者确认。

完成标准：长篇项目可以在一个页面中管理所有正文状态和历史。

### 3. 故事资料关系中心

- 为地点和势力提供独立编辑视图。
- 冲突按主线、支线、角色、章节建立生命周期。
- 事件视图复用时间线数据，支持章节、地点和参与者反向链接。
- 人物、地点、势力、事件、伏笔之间显示引用关系。
- 删除资料前检查引用并提供替换入口。

完成标准：每个故事实体只有一个事实来源，并且可以追踪所有引用。

### 5. 集中修订工作台

- 汇总人工批注、质量问题、连续性问题和待确认提案。
- 支持逐项接受、忽略、延期和批量处理。
- 显示修改前后差异与质量分变化。
- 将修订任务关联到章节、人物或伏笔。
- AI 未配置时仍可创建和处理人工修订任务。

### 6. Agent 上下文控制台

- 已实现本轮上下文 Token 预算、长期记忆与语义检索开关。
- 已实现资料固定/排除、对话分支、回复收藏和任务模板。
- 已实现工具白名单、只读/提案权限预设、轮次/工具/总 Token 上限。
- 已实现 Plan 模式，确认前禁止调用工具；思考过程和工具记录默认折叠。
- 待补充发送前费用估算与“每次调用前询问”的逐工具授权。

### 7. Agent 工具与模板扩展机制

- 从清单注册本地只读工具和提案工具。
- 导入、导出提示词包和工作流模板。
- 工具调用记录参数、结果、耗时和权限决策。
- 第三方工具运行在受限边界内，不能直接写项目文件。

### EPUB 导出配置

- 生成符合 EPUB 3 结构的电子书。
- 配置书名、作者、简介、语言、封面和版权信息。
- 配置分卷目录、章节标题和分页规则。
- 支持内嵌字体、段落样式和首行缩进。
- 导出前检查空章节、重复标题、缺失封面和无效链接。
- 保存项目级 EPUB 配置并提供导出预览。

## 不纳入本轮范围

- 全局搜索与命令面板。
- 各网文平台的专用发布配置。

保留通用 Markdown、TXT、DOCX 和 EPUB 导出，不维护平台规则。

## 推荐开发顺序

1. 强化人工写作工作台与 Agent 面板独立收起
2. 自动备份与恢复中心
3. 草稿箱与版本管理
4. 故事资料关系中心
5. 集中修订工作台
6. Agent 上下文控制台
7. EPUB 导出配置
8. Agent 工具与模板扩展机制

人工写作、保存、版本和备份构成基础闭环。AI 相关能力在这个闭环之上工作，并且始终保持可关闭、可审阅、可撤销。
