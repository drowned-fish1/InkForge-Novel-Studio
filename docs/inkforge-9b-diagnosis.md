# 9B 小说逻辑排查

日期：2026-10-10。目标是检查此前 Base/CPT 同题小说均混乱的原因；本轮没有启动 SFT、27B 下载或新训练。7组共24个样本已完成并完整保存。官方9B指令版也在这两题上出现基本逻辑错误，不能将原因只归到推理后端、采样、停止符或 Base 未经指令后训练。

## 已完成的对照

两题分别为“盐窟分账”和“黑市验蛊”，每题固定一个种子，全部输出保留。前者约束只有一只活蛊、空匣、二转/三转实力与需要引路的利益关系；后者约束只有十二块元石、二十块报价、有限试验工具与卖家未经证实的升级承诺。

| 条件                                         | 已观察到的问题                                                                                     | 能支持的判断                                                          |
| -------------------------------------------- | -------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------- |
| 原始 Unsloth，Base/CPT，原始文本提示         | 两版都有物品、交易与因果错误；CPT增加大量蛊道说明                                                  | 原始测试无法证明 CPT 提高小说逻辑                                     |
| 原生 Transformers，相同 Base/CPT 和采样      | Base重复收取预付款，且算“二十的三分之一”为六；CPT写“盐碟里没有盐，只有粗盐”并大段跑题              | 核心问题在独立实现中复现，不能主要归因于 Unsloth                      |
| 原生 Transformers，关闭采样                  | Base把卖蛊的交易写成店主付款给买家；CPT把唯一一只蛊写成两只，反复倒水循环                          | 随机采样不是必要条件；仅降低温度不足                                  |
| 同权重，官方聊天模板，默认 Base 停止符       | Base生成下一个虚构 user/assistant 回合；CPT一开始就写反空匣归属                                    | 模板和停止配置必须分别核对；模板本身不等于指令训练                    |
| 同权重，聊天模板，补齐回合结束符             | Base盐窟输出在731 token结束，不再编下一轮对话；CPT仍凭空出现四转蛊，黑市仍有两只野鸡和交易方向倒置 | 停止配置影响回合边界，未修复正文中的硬矛盾                            |
| 官方9B指令版，相同聊天输入与采样，明确停止符 | 盐窟出现“崩碎成粉”又成“完整的石印残片”；黑市只有12却写先7后余8，且反向循环付款                     | 指令版在此条件下也没有稳定守住基本事实；不能预设做过SFT便能解决       |
| 官方9B指令版，贪心解码，明确停止符           | 盐窟把仅能引路的蛊写成可延缓潮水，空匣又出现活蛊；黑市有12却提出付15                               | 不采样仍出现明确约束违例；两题均到700 token上限，不能判断最终收束质量 |

随机组保持此前温度0.8、top_p0.9、top_k40、repetition_penalty1.05、上限1100 token；这些是控制变量，不冒充官方推荐参数。贪心组 do_sample=False、上限700 token，故不能据此比较完成长度。每个条件只有两题各一个种子，不是正式总体能力评测；不同后端数值变化会改变随机输出，不能要求逐字一致。

## 加载、环境与数据检查

- Base 固定为 `Qwen/Qwen3.5-9B-Base` revision `68c46c4b3498877f3ef123c856ecfde50c39f404`。最终 CPT adapter SHA256 为 `63373c4ccca32a57065ff515246e9be2d487d25e9655cbf5cd228420292e4095`，29,097,984 个 LoRA 参数有限。
- 原始对照使用同一未合并模型，关闭/开启全部128个 LoRA 层；LoRA_B有16,515,072个非零参数。原生对照使用 PEFT 的 disable_adapter 上下文。相同条件下 Base/CPT 的输入 token 哈希一致。
- 原生实现使用 PyTorch2.8.0+cu128、Transformers5.17.0、PEFT0.21.2、BF16和SDPA，不导入 Unsloth。缺少 causal_conv1d、flash-linear-attention 时走参考 PyTorch 实现，日志说明该路径正确但慢；当前加载日志未见随机初始化、缺失权重或形状不匹配警告。
- 可选 torchao 与现有 Torch 版本不兼容，曾阻止原生进程启动。本轮只在新测试进程里隐藏未使用的 torchao，不修改训练环境。这个启动问题不能解释此前已成功生成的小说正文。
- Base 的默认 EOS 是 `<|endoftext|>`（248044）；聊天结束符是 `<|im_end|>`（248046）。补齐停止符的对照同时使用两者。原始 raw 测试未使用聊天模板，不能把后来发现的聊天回合结束问题当成它全部矛盾的原因。
- CPT 导出检查通过：214,286段、2,336来源单元；按 split 内顺序覆盖一次，原文哈希、token/labels一致、章节组互斥、含EOS不超过4096 token。训练集约459.6万 token；这个结构验收不等于语义训练效果验收。
- 现在试写的是正文 CPT，未做 SFT，DeepSeek 的场景标注尚未用于本次权重训练。因此当前错误不能归因于标注质量。标注本身仍需独立验收。
- 当前每题输入362/381 token，聊天格式408/427 token，加输出后远低于4096；这两段中的矛盾不属于“百万字上下文装不下”问题。

## 对此前验收的修正

验证集 loss 从3.06650下降到2.80244说明同域文本预测改善。它没有检验“只有十二块钱能否按正确方向买卖”“唯一物品是否保持归属”这类小说任务。CPT 文风和术语有所变化，但这些对照未显示逻辑改善。现有证据也不足以断言 CPT 导致全部混乱，或已证明9B容量不足。

后训练选模必须增加：硬事实违例、资源账目、人物知识边界、行动动机、重复与任务结束测试。不能把最低同域 loss 的 checkpoint 自动认定为最好的小说 writer。

## 官方指令版对照（已完成）

模型：`Qwen/Qwen3.5-9B`，固定 revision `c202236235762e1c871ad0ccb60c8ee5ba337b9a`。权重从 Qwen 发布的 ModelScope 仓库获取，每个文件核对固定 Hugging Face revision 的 SHA256或git blob SHA1；不因使用下载镜像而放弃版本核验。使用官方聊天模板、enable_thinking=False，同题同种子同采样参数；不加载 CPT adapter。

4个权重分片共19,306,310,880字节，已全部核验。官方指令版与 Base 补齐停止符组的两题输入 token 哈希逐题一致。模型配置 EOS 为248044，tokenizer EOS为248046；本轮明确同时设置两者，不能将指令版正文错误归因于遗漏回合停止符。

本轮没有测试思考模式或27B，也没有进行多种子或正式盲评；结果只说明这两题、这些参数下的稳定性不足，不证明所有9B均不适合小说，也不证明27B必定解决。采样指令版自然结束，无长循环，但仍有硬事实错误；不能把流畅、短小或自然终止当作逻辑正确。

下载核验后删除了20,872,883,424字节临时分块；两个正式模型和CPT权重均保留。检查时云盘约40GB可用，推理任务已退出；没有代用户关机。

## 新方向：文风草稿与逻辑编辑

依用户最新要求，制作了两段“现有CPT原稿→当前主助手逻辑编辑”的实样，见 `output/novel-training/guzhenren/dataset_v1/cloud/diagnosis-20261010/逻辑修订-文风保留对照.md`。原始草稿不覆盖，编辑来源明确，没有声称调用了另一家大模型或完成独立盲测。

保留有效原句、动作与利益叙事；同时给编辑器不可违反的事实和场景目标。盐窟中段因果已坏，需要较多重写；黑市也需改变错误的成交结局。不能把这两段描述为“只改几个词且保证文风完全不变”。后续可评估9B文风草稿→更强编辑模型→事实复核的流程，先验证样本质量与修改幅度，再决定SFT方向，不自动把示范入库。
