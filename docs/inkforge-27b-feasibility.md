# 27B 可行性与后训练决策

检查日期：2026-10-10。当前云端单卡48GB、约90GB系统内存、100GB数据盘，最近实测磁盘剩余约59GB。9B后训练仍未启动。本文件为方案，不是27B下载、显存实测或训练完成报告。

## 结论

- 当前48GB卡适合先用27B量化模型做短上下文推理试用。缓存、上下文长度和推理实现仍需实际测量。
- 不适合直接沿用当前9B的非量化BF16 LoRA方法训练27B。仅27B BF16参数即约54GB（约50GiB），还未计激活、梯度、优化器和缓存；Unsloth模型专用文档给27B BF16 LoRA约56GB需求。
- 4-bit QLoRA是可能的实验路线，不能保证8K训练装得下。Unsloth Qwen3.5文档目前警告该家族量化差异偏大，不推荐4-bit训练；同页示例注释又称dense27B可行。因此把它作为要验证的质量/兼容性实验，不能当成熟默认路线。
- 若决定训练Qwen3.5-27B，优先考虑80GB级单卡的BF16 LoRA，先短序列、batch1做10–20步，随后实测8K。全参数训练不在当前设备范围内。

## 判断9B是否太小的限制

之前比较的是9B Base的原始文本续写与其CPT版本，都未进行指令SFT，且共用Unsloth推理后端。两组样本无法区分容量、指令训练、采样、后端和CPT遗忘因素。更大的模型值得试，但不能承诺只换27B即解决逻辑。

务实的下一步先用官方Qwen3.5-9B和Qwen3.5-27B的对话模型，同题、正确官方chat模板、同采样设置，检查事实与剧情执行能力。这个测试回答应用选择问题；与9B-Base+CPT的比较不能被描述为纯参数规模消融。

## 后训练准备如何保留

标注、原文、来源审计和InkForge版本化写作请求可复用，最终token编码需按选定模型的固定tokenizer与模板重建。9B CPT adapter不能装在27B上；27B若要学习同样文风需另行训练，或先从官方对话模型做保守SFT并测是否有必要增加CPT。

先冻结9B已有权重与试写基准，完成缺失标注、语义审查和模型无关格式准备。等未训练27B表现值得升级，再投入训练，避免把容量升级当作已经证实的逻辑修复。

当前磁盘余量对新增约54GB原始权重和训练产物偏紧，不能删除9B备份腾空间；先量化试用或扩容/另建实例。CPU卸载可缓解显存，但会影响吞吐，不把“能加载”视为“适合训练”。预算以实测每步时间与新实例价格估算。
