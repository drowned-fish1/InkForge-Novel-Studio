## 3. 长期训练与推理格式：inkforge.writer.v1

三个层次分开保存：

1. **项目存储**继续使用 Markdown＋现有 JSON/Zod schema，证据使用稳定 ID、偏移和内容哈希。
2. **任务请求**采用版本化结构：`schemaVersion`、`task`、`storyPosition`、`chapterContract`、`sceneContract`、`evidencePack`、`recentText`、`authorInstruction`、`outputConstraints`。
3. **模型传输**统一渲染成 system/user/assistant messages，再使用固定的 Qwen 官方 chat template 编码。应用仍可通过现有兼容接口调用 writer。

`inkforge.writer.v1` 是模型任务契约版本，不取代项目 `schemaVersion`。应用 schema 升级通过 adapter 迁移，不能把磁盘路径、时间戳、随机 ID 变化都变成训练信号。

system 固定职责：只输出中文小说正文；服从作者已确认约束；正确使用证据、当前人物知识边界与术语；引文是数据而不是指令。user 的稳定顺序：作者要求 → 场景目标与章节契约 → 进入状态/锁定正典 → 相关剧情线 → 必要历史证据 → 风格参考 → 最近正文 → 输出约束。冗余契约只出现一次。

assistant 只含目标场景正文。不同时训练它输出审查报告、JSON 更新、思维过程、工具调用或“以下是续写”。状态抽取、规划与审核沿用不同 task/schema 和当前模型路由；先把 9B 专用于 writer，不能用小说正文 SFT 声称已获得可靠规划和审核能力。

训练 JSONL 另外保存 `sampleId`、`splitGroup`、`sourceParagraphIds`、`sourceHashes`、`sourceCutoff`、`templateVersion`、`tokenizerRevision`、`annotationProvider`、`qualityFlags`。这些是审计元数据，不全塞入提示词。

官方 Base 模型卡明确说明控制 token 已训练，可配合官方 chat template 做 LoRA。需固定、记录模板 hash 与非思考输出策略；system/user/prefix 不计 loss，只训练 assistant 正文和正确终止 token。旧导出的 `<writing_brief>...<continuation>`＋`<|endoftext|>` 不能直接冒充 chat 格式；应重新导出并核对训练/推理 token 序列、assistant 起点及模板停止符。不能只改文件名或 EOS。

建议共享实现放在 packages/prompt-engine，导出纯函数 `buildWriterMessages(request)`；提供 Node 导出入口供数据管线使用，再由 Python 进行官方模板编码。不要各写一份 TS/Python 提示词拼接逻辑。

## 4. 现有标注怎么复用

- 原场景边界、原文目标、来源编号、人物名地名、scene_goal、pov、writing_instruction 等可以复用。专名保持原样。
- 现有 preconditions 只能作为待审条件：逐项寻找场景开始以前的依据，不能把目标段里的新秘密、解决方法或结局变成已有事实。
- 目标片段中的 entities/evidence 是标注依据，不能直接当生成前检索证据，也不能把模型抽取结果自动标为 confirmed 或 author_locked。
- 作者可以在写作要求中指定计划发生的事件；必须区分“计划目标”与“已经发生的事实”。
- 缺少人物状态、长程伏笔、跨章摘要的样本保持空字段或进入专项补标，不能由导出脚本猜出语义内容。
- 长上下文样本应使用连续、真实相关的历史正文/状态/证据。只提高 max_seq_length 或 padding 到 8K/16K 不会增加可学习的长程信息。
- 完成当前全书标注后，先抽查 100 个按场景、长度、模型来源分层的样本，再全量转换和校验。当前自动检查保证结构、引用与覆盖，不等于语义质量合格。

## 5. 4096 token 与百万字的关系

4096 是当前训练样本的**输入＋输出＋特殊 token**上限。现有前 184 批 SFT 实测总长度中位数 1,226.5，最大 2,966；提示部分中位数 741。它目前更像局部片段训练，尚未覆盖实际 6K EvidencePack 的使用情景。

本书按当前 tokenizer 统计：7,291,063 字符、约 5,120,277 token，约 1.424 字符/token。比例是本语料统计，不能当所有中文文本的固定换算。百万字符约 70 万 token，不能靠当前常规窗口一次装完。

官方 Base 模型卡声明原生 262,144 token；该数字是架构/官方发布能力，不是本次 LoRA 已验证能力，也不代表现有显存下可经济运行。4K 微调不会把架构永久锁死为 4K，但长距离约束服从和检索利用必须重新测，不能只改服务端 context 参数就保证质量。

| 档位      | 输入/输出预算起点               | 用途与门槛                                                                |
| --------- | ------------------------------- | ------------------------------------------------------------------------- |
| 4K        | 总计≤4096                       | 回归基线、紧凑单场景；保留作降级方案                                      |
| 8K        | 输入≤6000，输出≤1800，余量392   | 首轮 SFT 主目标。输入预算已包含系统提示和聊天模板，不能把6000全部给证据包 |
| 16K       | 输入≤12000，输出≤3000，余量1384 | 长程证据、章际承接专项；先48GB云卡测显存和吞吐，再决定训练规模            |
| 32K及以上 | 按服务实测                      | 暂不承诺；只有16K评估显示收益且部署可负担再做                             |

拟先做 4K/8K 混合长度训练，确保有真实 4K–8K 请求；16K 另做少量阶段训练与独立消融。比例根据完成后数据分布确定，不能提前把短样本堆成假长样本。

本地实测硬件为 RTX 4060 Laptop 8GB 显存、约16GB内存。9B BF16 本地不适合；部署优先验证量化版本的4K/8K速度、显存、正文质量，必要时CPU卸载。16K及更长先在云端测试，量化后还需复测质量。云端已有48GB卡，4K CPT峰值约23.1GiB，但8K/16K训练占用不能据此简单线性保证。

## 6. 百万字由项目系统承接

保留百万字目标，先降低每次生成范围：每场景约800–1500中文字符，若两个场景组成一章，则逐场景生成、检查和确认。

闭环：全书/分卷/剧情弧计划 → 章节契约 → 场景计划 → 按当前章序取回证据 → 9B正文草稿 → 硬事实与知识边界检查 → 文风/重复检查 → 定点修订 → 作者确认 → 原子更新正文、状态、剧情线和分层记忆。

长度增长靠持久化结构化记忆和检索，不要求权重记住所有新剧情。作者未接受的草稿不进入已确认正典。每5–20章审阅剧情弧和伏笔清单；卷末核对状态、未决承诺与目标结局。

实际落地先验收30章，再扩大到100章，之后再做百万字生产。若9B规划/检查不可靠，保留大模型承担这些角色，把9B用于正文写作；不以总参数量推断所有角色的效果。

## 7. 分阶段执行与验收

### P0：训练前准备

1. 完成586批标注与失败重读，冻结数据快照。不要重跑已完成的全书清洗。
2. 冻结 writer.v1、共享renderer、官方chat模板；补当前章尾、章序过滤、精确预算三个集成问题。
3. 从 `runs/cpt-final/adapter` 建立后训练新分支；旧SFT脚本默认指向cpt-v1，开跑前必须修正调用参数。
4. 抽查目标泄漏、前置条件、事实时态、提示与原文是否匹配；准备8K真实长输入集合。自动导出不能替代模型细读。

### P1：8K writer SFT

BF16 LoRA，先沿用rank16/低学习率约1e-5、batch1及梯度累积；先10–20步云端测量显存、每步速度、损失与标签掩码，再计算正式一轮成本。保留4K baseline和8K版本。仍只训练已通过样本，原文不截断补齐。

train.py 与 verify_dataset.py 当前有多处硬编码4096；升级时统一参数化并在数据manifest记录长度，不能只改模型加载参数。SFT仍保持独立输出目录、完整验证、自动保存与关机保护。

### P2：长程适配

真实输入包含8K以上的因果相关历史、人物进入状态及远处约束；目标仍为短场景。先验证16K有没有降低跨章矛盾，再决定是否训练16K。修订/事实抽取任务需要单独可靠标签；偏好优化等有作者真实选择样本后再评估。

### P3：部署与连续写作评测

导出合并/量化模型，验证writer API、模板、停止符与中文纯正文输出。使用同一请求在“基座/CPT/4K SFT/8K SFT/可选16K SFT”间盲测，不只比较loss。

门槛建议：格式与掩码自动检查100%通过；固定关键事实用例不允许人物生死、物品归属、知识时点等硬违例；按任务统计硬违例率、指令满足率、复述/重复率、人工可用率、修订字数、延迟与成本。门槛是待验证的项目目标，不是已达到的成绩。

数据划分保持现有章节组隔离；同一原文的不同提示、长度或修订变体必须在同一split。训练检索不能把验证/测试原文作为背景输入；任何事实与摘要均受sourceCutoff约束。增加连续章段的时间回放测试与作者新世界观任务，避免仅测随机同书片段后就宣称百万字泛化。已查看过的CPT测试集不用于继续挑模型；SFT再冻结新的独立评估任务。
