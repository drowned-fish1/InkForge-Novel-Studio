# 交互检查与修复 · 2026-10-11

本轮承接上一轮 UI 修复，重点验证输入、保存、取消、切页、新建、批量操作、片段转章节，以及失败后的恢复。实际操作使用隔离的浏览器样本项目，未修改用户的小说文稿。

## 已修复的问题

| 问题                                 | 原来的实际影响                                                                    | 修复后的行为                                                                                                               |
| ------------------------------------ | --------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| 未保存内容在切条目、切页或新建时丢失 | 人物、世界观、术语、地点、势力、时间线、伏笔、冲突、事件的本地草稿被直接替换      | 有修改时提示确认；取消后保留原表单。切换模块、选择章节、新章、专注模式、关闭或打开项目均经过保护；页面关闭也注册未保存提示 |
| Ctrl+S 保存错对象                    | 编辑人物等表单时，快捷键仍保存章节正文                                            | 保存当前活动表单；草稿片段、导出配置、备份设置也有对应快捷保存。文件菜单改为“保存当前页面”                                 |
| 保存缺少反馈与失败处理               | 多个表单直接调用异步保存，用户不知道是否成功，失败没有可操作提示                  | 提示未保存、正在保存、已保存或失败；保存时禁用重复提交和删除；失败保留输入并允许重试；空白名称或标题不能提交               |
| 逗号和换行在打字时被吞掉             | 标签、别名、参与人物等每次按键就被 split/filter/join，刚输入的分隔符立即消失      | 保留原始输入和光标操作过程，支持中英文逗号、人物状态换行和中文输入法组合；保存时仍获得正确的数组                           |
| 保存成功后仍提示未保存               | schema 调整属性顺序或补默认字段，直接 JSON 字符串比较误判为修改                   | 比较忽略对象属性顺序；保存后采用存储层补齐的默认字段。保存期间继续输入时，保留新输入并继续标记为未保存                     |
| 指定分卷新章后打开了旧章节           | 创建章节后取整个章节列表最后一项；在较早分卷新建时，最后一项属于其他分卷          | 用创建前后的章节 ID 找出新章节并打开它                                                                                     |
| 批量选择包含筛选后看不见的章节       | 更改搜索或状态过滤后，旧选择仍参加归档、移动等操作                                | 改变筛选时清除选择；提供“取消选择”；批量执行时禁用行选择和冲突操作，单章归档错误也显示到页面                               |
| 灵感片段的保存、取消与转换不完整     | 空片段的保存按钮无反馈；错误未处理；编辑其他片段或取消可能丢内容                  | 空内容禁用保存；快捷保存、成功与失败反馈；取消或换片段有未保存保护；取消新章操作后不会继续覆盖原章节正文                   |
| 导出配置失败没有反馈                 | “保存配置”未捕获异常，离开页面会丢弃配置修改；保存期间新输入可能被旧配置覆盖      | 快捷保存和离开保护；保存失败提示并保留配置；保存期间有新修改时不覆盖；导出、检查和保存配置互斥                             |
| 备份参数被静默改成另一个值           | parseInt、默认值与范围夹取让非法、空白或小数输入被悄悄替换                        | 验证整数与明确范围，错误时保持输入并说明范围；有效设置可以 Ctrl+S 保存；未保存设置有离开保护                               |
| 快捷键与输入、弹窗冲突               | 已被局部编辑器处理的快捷键仍可能被全局处理，Ctrl+B 在普通文本框内触发全局专注模式 | 忽略已消费事件、重复事件与中文输入法组合；文本框内 Ctrl+B 不切换工作区；从其他模块进入专注时打开章节写作台                 |
| 窄窗口取消切页却关闭导航             | 导航按钮无论是否真正切页都关闭抽屉                                                | 切页成功才关闭；取消时保持抽屉和表单。Esc 关闭抽屉后保留编辑内容                                                           |

资料表单的确认使用浏览器/桌面运行时现有的原生确认交互，和当前产品中归档、删除等确认方式一致。点击已选中的同一条目不会重置正在编辑的内容。

## 验证

- **33 项表单检查通过**：9 个资料与剧情页面分别验证快捷保存、取消新建、取消切页；另验证连续输入逗号、换行、数组保存、空白名称和 Ctrl+B。
- **17 项工作流检查通过**：注入可恢复的保存失败与延迟，验证保留内容、重试、防重复提交、保存期间新输入；验证新章定位、批量选择、灵感片段转换、导出和备份设置。
- **6 项窄窗口与专注操作通过**：取消切页保持抽屉、取消新章不创建空章、关闭抽屉不丢内容、Esc 关闭、进入和退出专注模式。
- **原生确认框实测通过**：实际打开“未保存修改”确认并取消，原输入保持不变。批量表单回归中的取消分支使用受控 confirm 返回值，以避免 CLI 在原生弹窗出现时中断脚本。
- **重新加载后 20 个模块入口通过**：全部逐页打开，无扫描到的可见输入缺少名称或非滚动内容越界。
- **TypeScript 与 lint 通过**。
- **64 个测试文件、409 项测试通过**。新增测试覆盖拒绝离开时的状态与副作用、新章在正确分卷定位、局部快捷键与输入法保护。
- **构建和 diff 空白检查通过**。

## 范围与后续优化点

本轮覆盖浏览器中的真实表单与页面操作，保存失败通过替换样本项目的桥接方法模拟，测试结束后恢复。Electron 原生文件选择、真实磁盘权限错误和远端模型流式响应仍需要桌面运行验证。

进一步的体验改进可以集中在“资料引用选择”：时间线、伏笔等仍有需要手填 ID 或名称的字段，改为可搜索选择器会减少拼写和关联错误；全文搜索结果也可以进一步提供条目级定位和匹配内容高亮。这两项需要补充对应的数据选择交互，本轮未改动其数据模型。

检查过程中发现草稿箱和导出页两份源码异常成为全空字节，已保存异常副本并恢复有效源码、上一轮 UI 修改及本轮交互修改；随后完成类型、lint、测试和浏览器回归。工作区其他既有修改予以保留，本轮未提交或推送。
